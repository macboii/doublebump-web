# DoubleBump Web — Landing Page

## Project Overview

Static landing page for the DoubleBump iOS app. Single `index.html` file with embedded CSS and vanilla JS. No build step, no framework, no dependencies except the Google Fonts CDN.

## Stack

- **HTML/CSS/JS** — single `index.html`, zero dependencies
- **Font** — Press Start 2P via Google Fonts (pixel aesthetic)
- **Animations** — vanilla JS `requestAnimationFrame` loops
- **Hosting** — intended for GitHub Pages or Vercel static

## Analytics

- Google Analytics 4 (`gtag.js`), measurement ID `G-BP8MZZ3QJE` — installed in `<head>` of every page (`index.html` + all four legal pages). See [rules/architecture.md](.claude/rules/architecture.md) for placement convention.
- UTM campaign params (`utm_source`/`utm_medium`/`utm_campaign`/`utm_content`) on inbound links are read automatically by GA4's default campaign attribution — no custom code needed. Cold-outreach campaign links are generated by the sibling `doublebump-campus-seed` project.
- Store CTA clicks fire `app_store_click` / `google_play_click` events (`platform`, `cta_location` params) — see the bottom-of-`index.html` script tracking `.store-buttons a` clicks across `#hero`/`#tryit`/`#cta`.
- `/ios` and `/android` are cold-outreach tracking redirects (`ios/index.html`, `android/index.html`): read `utm_source`/`utm_medium`/`utm_campaign`/`utm_content` from the query string, then redirect to the real App Store / Google Play URL. `/android` also re-encodes the UTM values as a Play Install Referrer string on the destination URL. Both destinations are hardcoded — no open-redirect surface. `noindex, nofollow`, not in `sitemap.xml`. Not app-install attribution, just click measurement.
- These two redirect pages disable `gtag('config', ..., { send_page_view: false })` and send `page_view` manually (with `page_location: location.href`, so GA4's own campaign parsing sees the UTM-bearing URL) alongside `store_redirect` — both gated on `event_callback`, with a redirect only once both land (or an 800ms fallback fires). This exists because the page leaves almost immediately: the default automatic `page_view` has no send guarantee against that, and a fast redirect can outrun gtag.js's async load, leaving the session's campaign attribution `(not set)`. Don't drop this pattern if these pages are ever simplified — it's the fix for a real observed bug, not defensive boilerplate.

## Deploy

No build step. Deploy `index.html` directly.

- **GitHub Pages**: push to `main`, enable Pages from root
- **Vercel**: drag-and-drop or connect repo — auto-detects static
